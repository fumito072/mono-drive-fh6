# 映像の時間変化と操舵を学ぶ

従来のPathNetは単画像から軌跡を推定する。追加したモデルは、時計で対応を確認したWRXの人間プレイ記録から、約5Hz・9枚（過去約1.6秒）の景色、速度、過去のData Out操舵値を入力し、次の3サンプル（約0.2〜0.6秒）の平均操舵値を予測する。

Data Outの操舵はゲームが報告する値であり、物理コントローラーの生入力ではない。操舵とヨー角速度の相関から観測した応答遅れと、ファイルの時計同期ずれを混同しない。時刻は変更せず、入力には現在・過去だけを含める。

## 学習・比較

1. `python tools/prepare_temporal_driving.py` で準備済み教師データから特徴を抽出する。停止、時刻の飛び、記録の切れ目、別車種、同期未確認の録画を跨がない。
2. `python tools/train_temporal_steering.py --wait` で学習する。CNNはFH6教師映像に未学習の既存基礎モデルから固定し、約同規模のGRUと単画像ヘッドを比較する。
3. 一部の録画を丸ごとテスト用に残し、その録画のどの区間もヘッドの学習に使わない。別の検証区間で最良の回を選択する。
4. 操舵誤差、曲がる場面の誤差、時間差分の誤差、方向別の誤差を評価する。履歴を現在の画像で置き換えた比較も行う。

固定CNNも教師データの車線位置の正解を知っているわけではない。単画像の基礎モデルは別ゲーム由来で、画角や画像分布の差がある。評価結果はその条件での実測値として扱う。

`python tools/render_temporal_report.py --wait` はテスト用録画の一部に、操舵と予測を重ねた確認用動画を作る。動画は抽出済みの約5fpsフレームから作成し、元の音声は含まない。

## 走行への反映

初期状態は `configs/temporal_steering.json` の `mode: shadow`。予測を記録し、操作には使わない。単画像比較と実走の一致度を通った場合のみ、小さな試験補正へ進む。

- 車種、時間間隔、前進状態、認識品質を確認する。
- 不確かな車線、後退、復帰、障害物回避などでは介入しない。
- 既存の操舵との差が大きい予測を拒否する。
- 補正は正規化操舵値の最大0.025まで。車体が車線内に収まる余裕と道路面の根拠を確認する。
- ペダル、カメラ、メニューは変更しない。既存のアナログ平滑化を通す。
- 試験中の接触・復帰があれば補正を止め、観測に戻す。

`python tools/evaluate_temporal_live.py` はこの最初のモデルの観測・試験を監視する。実走試験の通過も60km/hで安定走行できることの保証ではない。新しいモデルを同じパスへ書き込みながら使用せず、学習を終えて検証した候補を使う。

設定が有効なローカルの継続セッションでは、`mono_drive.forza_temporal_worker` が新しい検証済み教師データの版を監視する。初回の学習が終わってから、追加データに対して別名の候補を学習し、オフライン比較を通った候補だけを観測・試験へ送る。元の動画と教師の時計情報は変更しない。

## 元動画をより多く使う

`tools/prepare_dense_temporal_video.py` は検証済みWRXの元動画から約10fpsで再抽出する。録画の72%以降という既存の検証区間を保ち、その直前の8秒を空けて学習範囲を延ばす。従来の47〜72%にあった大きな未使用区間を学習に戻し、同期の欠落・メニュー・激しいスリップを跨がない。

10fpsの各時刻を学習例の起点にし、履歴は1枚おきの9枚、約1.6秒を維持する。未来の正解も約0.2・0.4・0.6秒先を使う。単なる画像複製や再生速度の変更はしない。走行側の推論周期は5Hzのままなので、学習密度を上げても制御周期の負担を倍にしない。

ローカルのワーカーはこの高密度版で24エポック、最大12万例/エポックを学習する。追加録画を検出した場合も同じ手順を使う。全体精度が単画像比較を上回らない候補は運転に反映しない。

2026-11-03の最初の5fps比較では、独立テスト13,914例で曲がる場面の誤差は0.15682から0.15016に減った。一方、全体誤差は0.06910から0.07078へ増えたため不採用とした。この結果は「滑らかさだけで採用しない」ための基準例であり、60km/h走行の達成を示さない。
