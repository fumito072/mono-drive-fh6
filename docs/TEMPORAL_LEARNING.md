# 映像の時間変化と操舵を学ぶ

## 操作量がない記録の利用

利用可能な正解を区別する。時刻の対応が確認できる位置・向きの記録と画像がある場合、既存の `Drive` / `train_pathnet.py` は `actions.csv` を必要とせず、その後に実際に通った軌跡を教師にできる。速度があっても、アクセル・ブレーキ・操舵の実測値と同じものとして扱わない。

今回の空記録38件は操作量だけでなく、位置・速度のパケットも保存されていなかった。このため `prepare_uncontrolled_video.py` は元動画の実フレームと時刻から画像の相対運動を抽出する。特徴点の往復対応、外れ値除去、画面内での広がりを確認し、静止画面や不連続な変化を除外する。単眼映像だけからメートル単位の位置やkm/hを得たとは記録しない。

`run_uncontrolled_video_learning.py` はこの弱い画像運動を補助課題として画像特徴に学習させ、操作量が正しく残る別の教師記録で効果を検証する。画像運動から架空のハンドル・ペダル正解を作らない。採用前には通常の独立テストと実走試験を必要とする。

## 時系列補正の比較候補

`train_temporal_steering.py --variant residual` では、単画像モデルを先に学習して検証で選び、その重みを固定して履歴による小さな補正を学習する。通常のGRUモデルと独立した候補として保存する。補正なしの状態から始め、検証と録画単位のテストを経て判断する。検証基準は通常候補と同じであり、この構成だけで改善や60km/h走行を保証しない。

2026-11-03の残差候補は単画像8周・補正16周で学習し、独立テスト13,914例で固定した単画像との比較条件を通過した（操舵MAE 0.064962対0.066562）。別の24周単画像モデルはMAE 0.065978だった。したがって固定単画像比の2.4%改善を、同じ計算量のすべての単画像方式に対する優位性とは解釈しない。

初回のゲーム内観測では、補正を有効にする前に従来の運転側で路外判定と停止が発生した。記録された走行48秒の平均速度は20.8km/hであり、60km/h目標は未達。候補の操作反映は0回で、実走で採用可能かの結論は保留とした。オフライン合格だけで運転品質の改善を主張しない。

従来のPathNetは単画像から軌跡を推定する。追加したモデルは、時計で対応を確認したWRXの人間プレイ記録から、約5Hz・9枚（過去約1.6秒）の景色、速度、過去のData Out操舵値を入力し、次の3サンプル（約0.2〜0.6秒）の平均操舵値を予測する。

Data Outの操舵はゲームが報告する値であり、物理コントローラーの生入力ではない。操舵とヨー角速度の相関から観測した応答遅れと、ファイルの時計同期ずれを混同しない。時刻は変更せず、入力には現在・過去だけを含める。

## 学習・比較

1. `python tools/prepare_temporal_driving.py` で準備済み教師データから特徴を抽出する。停止、時刻の飛び、記録の切れ目、別車種、同期未確認の録画を跨がない。
2. `python tools/train_temporal_steering.py --wait` で学習する。CNNはFH6教師映像に未学習の既存基礎モデルから固定し、約同規模のGRUと単画像ヘッドを比較する。
3. 一部の録画を丸ごとテスト用に残し、その録画のどの区間もヘッドの学習に使わない。別の検証区間で最良の回を選択する。
4. 操舵誤差、曲がる場面の誤差、時間差分の誤差、方向別の誤差を評価する。履歴を現在の画像で置き換えた比較も行う。

固定CNNも教師データの車線位置の正解を知っているわけではない。単画像の基礎モデルは別ゲーム由来で、画角や画像分布の差がある。評価結果はその条件での実測値として扱う。

`python tools/render_temporal_report.py --wait` はテスト用録画の一部に、操舵と予測を重ねた確認用動画を作る。動画は抽出済みの約5fpsフレームから作成し、元の音声は含まない。

## 走行への反映

初期状態は `configs/temporal_steering.json` の `mode: shadow`。予測を記録し、操作には使わない。単画像比較と実走の一致度を通った場合のみ、小さな試験補正へ進む。

- 車種、時間間隔、前進状態、認識品質を確認する。
- 不確かな車線、後退、復帰、障害物回避などでは介入しない。
- 既存の操舵との差が大きい予測を拒否する。
- 補正は正規化操舵値の最大0.025まで。車体が車線内に収まる余裕と道路面の根拠を確認する。
- ペダル、カメラ、メニューは変更しない。既存のアナログ平滑化を通す。
- 試験中の接触・復帰があれば補正を止め、観測に戻す。

`python tools/evaluate_temporal_live.py` はこの最初のモデルの観測・試験を監視する。実走試験の通過も60km/hで安定走行できることの保証ではない。新しいモデルを同じパスへ書き込みながら使用せず、学習を終えて検証した候補を使う。

設定が有効なローカルの継続セッションでは、`mono_drive.forza_temporal_worker` が新しい検証済み教師データの版を監視する。初回の学習が終わってから、追加データに対して別名の候補を学習し、オフライン比較を通った候補だけを観測・試験へ送る。元の動画と教師の時計情報は変更しない。

## 元動画をより多く使う

`tools/prepare_dense_temporal_video.py` は検証済みWRXの元動画から約10fpsで再抽出する。録画の72%以降という既存の検証区間を保ち、その直前の8秒を空けて学習範囲を延ばす。従来の47〜72%にあった大きな未使用区間を学習に戻し、同期の欠落・メニュー・激しいスリップを跨がない。

10fpsの各時刻を学習例の起点にし、履歴は1枚おきの9枚、約1.6秒を維持する。未来の正解も約0.2・0.4・0.6秒先を使う。単なる画像複製や再生速度の変更はしない。走行側の推論周期は5Hzのままなので、学習密度を上げても制御周期の負担を倍にしない。

ローカルのワーカーはこの高密度版で24エポック、最大12万例/エポックを学習する。追加録画を検出した場合も同じ手順を使う。全体精度が単画像比較を上回らない候補は運転に反映しない。

元のフレームレートが15fps等の場合も、実際の時刻に沿った10Hzの選択を行う。重複フレームで10fpsを作らない。完了した候補ごとに `out/temporal-report/<候補名>/` へ、景色・実操舵・未来予測の比較動画を保存する。

2026-11-03の最初の5fps比較では、独立テスト13,914例で曲がる場面の誤差は0.15682から0.15016に減った。一方、全体誤差は0.06910から0.07078へ増えたため不採用とした。この結果は「滑らかさだけで採用しない」ための基準例であり、60km/h走行の達成を示さない。

## 画像の特徴も教師動画で調整する

`tools/train_visual_encoder.py --out models/visual_encoders/<任意名>` は画像の後半の畳み込み層と特徴射影を学習する。現在の画像・速度から、少し先の平均操舵と向きの変化を同時に予測する。特徴抽出を固定した比較モデルも同じ画像・同じ学習回数で学習し、検証誤差が改善しなければ元の画像特徴を残す。

時系列モデルの最終テスト用録画は、この段階にも一切含めない。検証区間の画像を学習に混ぜない。画像の明るさを小さく変える以外の幾何変換は加えず、左車線やカメラ位置の意味を保つ。

`configs/temporal_steering.json` で `visual_finetune: true` にすると、高密度版の特徴抽出の前にこの比較を行う。同じ元データ・同じ基礎重みの比較結果がある場合は再利用し、異なる録画へ無条件に適用しない。その後の時系列比較と実走試験は引き続き必要である。

`tools/run_visual_refinement.py` は画像部分の比較を待ち、通過した場合は既存の検証済みデータでも新しい特徴による時系列モデルを学習する。高密度版の抽出完了を待たずに次の検証へ進める。画像部分だけを走行中のモデルへ入れ替えず、対応する時系列ヘッドを必ず再学習する。

最初の8エポック比較は2026-11-03に完了した。検証用6,000例で、固定した画像特徴との比較では操舵MAEが0.082738から0.074676へ（9.74%減）、曲がる例のMAEが0.183934から0.160391へ（12.80%減）、向きの変化のMAEが0.056866から0.047332へ（16.77%減）となり、画像部分の採用基準を通過した。方向の誤差は45度を1とする正規化単位。最終テスト用の7録画はこの学習に入れていない。これは画像特徴の検証結果であり、完成した運転方策や実走速度の改善を示すものではない。

## 操作データの有無を調べ直す

`tools/audit_teacher_controls.py` は録画の終了フラグだけを信頼せず、CSVの実データ行と生の受信レコードを確認する。エラー扱いでも実データがあれば同期検証の候補に残し、ヘッダーだけのファイルを操舵の教師として使わない。元ファイルは変更しない。診断結果は個別の保存場所を含むため、通常の公開Gitには入れない。

2026-11-03の再調査では、失敗した38録画すべてでCSVは見出しのみ（1,693バイト）、生の受信記録はヘッダーのみ（8バイト）だった。これらの約107万映像フレームに有効な操作対応行はなかった。関連する78ファイルの過去版、28ショートカット先、同じ時計で重なる記録、既存ZIP、PC内の追加候補も確認し、新しい復旧元は見つからなかった。以前の同期修復で復旧したデータは引き続き別途使う。今回の範囲では、収集されていない実入力を推測で補って正解ラベルとはしない。

## 操作がない映像と実走評価

`tools/run_uncontrolled_video_learning.py` は、操作記録がない動画から約2Hzで実在するフレームだけを取り出す。ファイル名には元動画のPTSを使う。特徴点の往復追跡と外れ値除去で画像上の相対的な動きを推定し、低い重み（0.04）の補助損失として画像モデルへ与える。静止画、長い欠落、追跡に失敗した区間は使わない。画像上の動きはメートル単位の速度や世界座標ではなく、操舵の正解にも変換しない。

実測の位置・速度がある教師は、従来どおり将来の走行軌跡や向きの変化を学ぶために使う。実測がない動画に座標や速度の正解を捏造しない。補助情報を加えた候補も、実操作つきの独立した検証を通った場合だけ次へ進める。最初の依頼分の走行評価を優先し、その完了後に追加の補助学習を進める。

実行時の画像間隔の揺れは、現在以前の観測だけを時刻に沿って補間して扱う。0.5秒より大きい欠落は使わない。学習でも途中の画像が欠けた例を作り、独立テストで誤差が大きく増えないことを確認する。

`tools/evaluate_temporal_live.py` はまず観測のみで比較し、その後に小さく制限した操舵補正で走行する。走行時間、平均速度、55〜65km/hにいた割合、観測できた車線での中央維持、操舵・ペダルの変化、接触・復帰を記録する。認識できない車線を中央維持の成功例に数えない。学習済みの補正を採用する判断と、60km/h付近の走行目標を達成したという判断は別に保存する。
